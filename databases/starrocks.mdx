---
title: StarRocks
description: Connect to StarRocks on its MySQL port and browse default_catalog and external catalogs such as Iceberg and Hive
---

Point the connection at a frontend's MySQL port, 9030, not the 8030 HTTP port. The bundled MySQL driver connects, then confirms the server is StarRocks with `SELECT current_version()`; a MySQL server saved under this type fails at connect and asks for the type to be changed. No minimum StarRocks version is enforced.

## Quick setup

A single-node cluster in Docker:

```bash
docker run -d -p 9030:9030 -p 8030:8030 -p 8040:8040 starrocks/allin1-ubuntu
```

Connect as `root` with an empty password once the frontend reports ready, about a minute after start.

## Connection settings

| Field | Default | Notes |
|-------|---------|-------|
| **Port** | `9030` | The frontend's MySQL port |
| **Database** | empty | Optional. `catalog.database`, a catalog, or a database of `default_catalog` |
| **SSL Mode** | Preferred | TLS first, plain text if the server refuses |

Host, user, password and SSH tunnels work as on [MySQL](/databases/mysql).

## Connection URL

No URL scheme opens a StarRocks connection. Create it in the form. **Copy Connection String** gives a `mysql://` URL, which other MySQL clients accept.

## Catalogs and databases

Catalogs fill the database level and each catalog's databases fill the schema level, so the sidebar shows `default_catalog` and every external catalog, with their databases beneath. `Cmd+K` switches catalog, and the database picker switches database within it.

The Database field takes the same two levels. Write `glue_iceberg.sales` to open on database `sales` in catalog `glue_iceberg`. A name with no dot opens that catalog when the server has one, and otherwise a database of `default_catalog`. Leave the field empty to start in `default_catalog`.

Materialized views in `default_catalog` list apart from views, and open on their `CREATE MATERIALIZED VIEW`. The sidebar hides `_statistics_`, `information_schema` and `sys`.

## Editing rows

What a save can do depends on the table's key model. Edits save one statement at a time with no transaction.

| Key model | Row matched on | Edit a cell | Delete a row |
|---|---|---|---|
| Primary key | Key columns | Yes | Yes |
| Unique key, aggregate key | Key columns | No, the server refuses `UPDATE` | Yes |
| Duplicate key | Every column | No, the server refuses `UPDATE` | Yes |
| External catalog table | Every column | Up to the connector | Up to the connector |

A match on every column leaves out ARRAY, MAP, STRUCT, JSON, BITMAP, HLL, PERCENTILE, BINARY and VARBINARY columns. To change a row the server refuses to update, delete it and insert it again in the SQL editor.

JSON and VARIANT columns read as text in the grid and the inspector.

## Limitations

- No indexes, foreign keys, triggers, routines, events or partitions. The Structure tab shows columns, with key columns marked, and does not edit them.
- No Create Database, Drop Database, renames or import. Create catalogs and databases in the SQL editor.
- The table info panel shows row counts and sizes for `default_catalog` tables only. An external catalog's tables show none.
- `EXPLAIN ANALYZE` is not in the plan menu. Run it in the SQL editor; its report carries terminal color codes.
- No Users & Roles, Server Dashboard or Table Maintenance.
- Not available on iPhone and iPad.
