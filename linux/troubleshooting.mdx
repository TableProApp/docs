## Passwords

Saved passwords live in the Secret Service, the desktop keyring that GNOME Keyring, KWallet and KeePassXC provide, and never in a file.

### Every connect asks for the password

No Secret Service is running, so there is nowhere to keep the password, and the prompt has no **Remember Password** switch. Check for one:

```bash
busctl --user list | grep org.freedesktop.secrets
```

No line means none is installed or none can start. Install one, then log in again:

- GNOME and most other desktops: `gnome-keyring` (`sudo apt install gnome-keyring`, `sudo dnf install gnome-keyring`).
- KDE Plasma: KWallet (`kwallet6` on Ubuntu, `kf6-kwallet` on Fedora), which Plasma installs by default.
- KeePassXC: turn on Secret Service Integration in its settings, and leave it running.

The packages recommend one of these, so a normal install has one. A minimal install or a window manager session may not.

### A saved password is asked for again

The keyring is locked. The desktop asks to unlock it when a saved password is read; dismiss that prompt and the app asks for the password instead. A keyring that never unlocks at login usually has a different password from the account, after a password change or with automatic login. Passwords and Keys (Seahorse) or KWallet Manager changes the keyring password to the login password.

The saved entries are named `TablePro database password for …`, `TablePro SSH password for …` and `TablePro SSH key passphrase for …`.

## SSH tunnels

The tunnel runs the system `ssh` and reads `~/.ssh/config`, `~/.ssh/known_hosts` and the SSH agent as a terminal does. When a tunnel fails, try the same hop in a terminal first:

```bash
ssh -v -J jump.example.com user@bastion.example.com true
```

### Agent sign-in fails

The app uses the agent that `SSH_AUTH_SOCK` names in the desktop session, and `ssh-add -l` lists the keys it holds. When the key works in a terminal and not in the app, the desktop session has a different agent or none: `systemctl --user show-environment | grep SSH_AUTH_SOCK` shows what apps started from the desktop get.

### Unknown host key

The server's SHA256 fingerprint shows before anything connects, even where `ssh_config` says `StrictHostKeyChecking accept-new` or `no`. Compare it with `ssh-keygen -lf` on the server's key, or with what the server's administrator gives you.

### Changed host key

**Review Key** in the connection's banner replaces the entry in `known_hosts`. Under `StrictHostKeyChecking yes` it cannot: run `ssh-keygen -R host`, then click **Retry**. A revoked key is refused, with no way past it in the app.

## SQL Server with Kerberos

**Windows (Kerberos)** uses the ticket `klist` shows. `kinit` and `klist` come in `krb5-user` on Ubuntu and `krb5-workstation` on Fedora.

```bash
kinit you@EXAMPLE.COM
klist
```

### KRB5KDC_ERR_S_PRINCIPAL_UNKNOWN

The server's service principal, `MSSQLSvc/<host>:<port>`, is not in the realm the lookup used. It is built from the host and port you typed and looked up in `default_realm` of `/etc/krb5.conf` only. Type the host name the SPN is registered for, not an IP address or a CNAME. A server in another realm works only when your KDC answers with a referral, as Active Directory does inside a forest.

A missing or expired ticket fails the same login: run `kinit` again, then retry.

## Logs and crash reports

Started from the desktop, the app writes its log to the journal:

```bash
journalctl --user --boot | grep -i tablepro
```

For a detailed log, quit the app first, since a second launch hands over to the running one and exits. Then start it from a terminal:

```bash
RUST_LOG=debug tablepro 2> tablepro.log
```

The log names your hosts, databases and tables, so read it before you attach it. It never holds passwords.

Each crash writes a report to `~/.local/state/tablepro/crashes/`, and the next launch offers **Show Report**. Nothing is uploaded.

## Reporting a bug

Open an issue at [github.com/TableProApp/TablePro/issues](https://github.com/TableProApp/TablePro/issues) with:

- The text from **About TablePro > Troubleshooting > Debugging Information**. **Copy Text** puts it on the clipboard. It holds versions and no connection details.
- Where the app came from (the PPA, COPR, a .deb, .rpm or Flatpak bundle from GitHub Releases, or a source build), the distribution and its version, and the desktop and session: `echo $XDG_CURRENT_DESKTOP $XDG_SESSION_TYPE`.
- The log and the newest crash report from the same time, when there is one.

## After a downgrade

An older version never changes a file a newer one wrote. It refuses the file until the newer version is installed again or you reset it:

- The connection list shows "Saved connections were created by a newer version of TablePro". **Reset…** moves the file aside, under a name the toast shows, and starts an empty list.
- A connection's saved tabs do not reopen, and a toast says "Saved tabs could not be read", with **Reset**.
- The query history says it could not be read.

Installing the newer version again brings all of it back, unless it was reset.

## Where the files are

| Path | Holds |
|---|---|
| `~/.config/tablepro/connections.json` | Saved connections, without passwords |
| `~/.config/tablepro/column_widths.json`, `filter_settings.json` | Column widths and filters per table |
| `~/.local/state/tablepro/history.db` | Query history and saved queries |
| `~/.local/state/tablepro/workspaces/` | Each connection's tabs, and the connections open at the last quit |
| `~/.local/share/tablepro/drafts/` | The text of each SQL editor tab |
| `~/.local/state/tablepro/crashes/` | Crash reports |

Preferences are in GSettings: `gsettings list-recursively app.tablepro.TablePro` lists them, and `man tablepro` has the same list.

The Flatpak bundle uses `~/.var/app/app.tablepro.TablePro/config/tablepro/`, `.local/state/tablepro/` and `data/tablepro/` in place of `~/.config/tablepro/`, `~/.local/state/tablepro/` and `~/.local/share/tablepro/`. There, the preferences and a detailed log come from:

```bash
flatpak run --command=gsettings app.tablepro.TablePro list-recursively app.tablepro.TablePro
flatpak run --env=RUST_LOG=debug app.tablepro.TablePro 2> tablepro.log
```
