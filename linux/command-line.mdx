The `tablepro` that starts the app is also its command line. A first word that names a command runs
in the terminal and prints there; a file, a URL or no argument at all opens the app.

<CodeGroup>

```bash .deb and .rpm
tablepro query -c Staging "SELECT id, email FROM users LIMIT 5"
```

```bash Flatpak
flatpak run app.tablepro.TablePro query -c Staging "SELECT id, email FROM users LIMIT 5"
```

</CodeGroup>

The rest of this page writes `tablepro`. For Flatpak, put `flatpak run app.tablepro.TablePro` in its
place, or add `alias tablepro='flatpak run app.tablepro.TablePro'` to your shell's startup file.
`tablepro --help` lists the commands, `tablepro help query` explains one, and `tablepro --version`
prints the app's version.

## Before the first command

Commands go through the app's [MCP server](/integrations/mcp-clients#tablepro-for-linux), so two
things have to hold:

<Steps>
  <Step title="Start TablePro">
    The server runs only while the app is open, and a command never starts it. With the app closed,
    a command exits 1 and says TablePro is not running.
  </Step>
  <Step title="Turn on the MCP server">
    Turn on **Preferences > MCP > Enable MCP Server**. With it off, a command exits 3.
  </Step>
</Steps>

`tablepro status` checks both without starting anything. It exits 0 when a command can run now, 1
when TablePro is not running, and 3 when the server is off.

There is no pairing step. Each run reads the server's access token from the keyring where the app
keeps it, so **Regenerate Access Token…** needs nothing on the command line. A Flatpak command reads
the sandbox's own copy: run the command from the same installation as the app, since a native
`tablepro` cannot read a Flatpak app's token, nor the other way round.

## Open files and connection URLs

```bash
tablepro app.sqlite3 sales.duckdb
tablepro "postgresql://ada@db.example.com:5432/shop"
tablepro --new-window schema.sql
```

A database file opens as a session, as in [SQLite and DuckDB files](/linux/connect#sqlite-and-duckdb-files),
and a `.sql` file opens in an editor tab. `--new-window`, or `-n`, opens them in a new window.

`tablepro <file>` is short for `tablepro open <file>`. A word that is neither an existing file nor a
URL opens nothing and exits 2. A file named like a command, such as `tables`, opens with `./tables`
or `tablepro open tables`.

### Connection URLs

These schemes open in TablePro from a terminal, and from a link in a browser or any other app:

| Engine | Schemes |
|---|---|
| PostgreSQL | `postgresql`, `postgres` |
| MySQL and MariaDB | `mysql`, `mariadb`, `mysqlx` |
| SQL Server | `sqlserver`, `mssql` |
| ClickHouse | `clickhouse`, `ch` |
| Cassandra and ScyllaDB | `cassandra`, `cql`, `scylla`, `scylladb` |
| Redis | `redis`, `rediss`, `valkey`, `valkeys` |
| MongoDB | `mongodb`, `mongodb+srv` |
| SQLite | `sqlite`, `sqlite3` |
| DuckDB | `duckdb` |

A URL that matches a saved connection asks before opening it. `Enter` and `Escape` both cancel, so
click **Open** to go ahead. Any other URL opens the connect dialog filled from it: check the host,
user and database, then click **Connect**, which saves the connection once it connects. A password in
the URL goes to the **Password** row only, and is never logged or shown.

## Run a query

```bash
tablepro query -c Staging --format csv "SELECT id, email FROM users LIMIT 5"
tablepro query -c Staging -f report.sql > report.csv
echo "SELECT count(*) FROM orders" | tablepro query -c Staging --format json
```

`-c` takes a saved connection's name or id, and `tablepro connections` lists both. The SQL comes
from the argument, from `-f <file>`, or from standard input, and `-f -` reads standard input even at
a terminal. Under Flatpak, `-f` reads files in your home folder, `/media`, `/run/media` and `/mnt`;
pass any other file on standard input.

SQL that starts with a dash, such as a leading `--` comment, goes after `--`, which ends the options:

```bash
tablepro query -c Staging -- "-- weekly report
SELECT count(*) FROM orders"
```

| Option | |
|---|---|
| `--database` | A database already open in the connection's window: its own, or one added with **Open Database…** on its sidebar row. Without it, the connection's own database |
| `--format` | `csv`, `tsv`, `json`, `jsonl` or `table`. `table` on a terminal, `csv` into a pipe or a file |
| `--limit` | Rows to return, 100 by default and 1,000 at most |
| `--timeout` | Seconds the statement may run, 1 to 300, 30 by default |
| `--read-only` | Refuse any statement that is not a read, even on a connection set to **Read & Write** |

`query` has no `--schema`. Qualify table names in the SQL instead, as in `public.orders`. A result cut
short by `--limit` says so on standard error.

### The connection has to be open

A command that names a connection works on a session open in TablePro. Run from a terminal, it opens
a closed connection in a window, which may ask for the password, and waits up to 5 minutes for it to
connect. Run from a script or a cron job, where standard error is not a terminal, it exits 1 instead:
open the connection in TablePro first.

### What a query may do

- The connection's **External Clients** level: **Blocked** hides it, so the command exits 2 as for an
  unknown name. **Read Only**, the default, refuses writes.
- On **Read & Write**, a write runs only after you click **Run** in the connection's window.
- The connection's Safe Mode applies, as in the editor.
- One statement per run, or one batch on SQL Server.

## Browse a schema

```bash
tablepro connections --format json
tablepro databases -c Staging
tablepro tables -c Staging --schema public
tablepro describe -c Staging --schema public orders
tablepro describe -c Staging --ddl orders
```

<CliSchemaCommands />

`--database` reaches only a database already open in the connection's window, as for `query`.

## Export a table

```bash
tablepro export -c Staging --format csv orders > orders.csv
tablepro export -c Staging --format sql orders > orders.sql
```

`--format` is `csv`, `json` or `sql`, and `sql` writes `INSERT` statements in the engine's own
quoting. Each table stops at 1,000 rows, and a table cut short says so on standard error. For every
row, open the table and use [Export Rows…](/linux/data-grid#copy-and-export) on every saved row.

## Shell completion

The .deb and .rpm packages install completions for bash, zsh and fish. Open a new shell after
installing, and `Tab` completes commands, options and `--format` values; zsh needs `compinit` in
`~/.zshrc`, as most setups have. Connection names do not complete. Flatpak installs no completions.

`tablepro completion bash`, `zsh` or `fish` prints the same script.
