title: Privacy
description: "Every outbound request the app can make, what each one carries, and where its off switch is"
---

Three requests leave a stock install without you asking: usage data to PostHog, an update check, and a fetch of the plugin catalog. None of the three carries a query, a row, a hostname, or a password. A Mac updated from a version that held a license key also trades that key once for a sign-in. Every other channel in this table is one you switch on yourself.

| Channel | Goes to | On by default | Off switch |
| --- | --- | --- | --- |
| [Usage data](#usage-data) | `eu.i.posthog.com`, `eu-assets.i.posthog.com` | Yes | **Settings > General**, under Privacy |
| [Update check](#update-checks) | `updates.tablepro.app` | Yes | **Settings > General**, under Software Update |
| [Plugin catalog](#the-plugin-catalog) | `updates.tablepro.app` | Yes | None |
| [AI provider](#ai-providers) | whichever provider you add | No provider is configured on a fresh install | Delete the provider, or turn off **Enable AI Features** |
| [iCloud sync](#icloud-sync) | your own iCloud account | No | **Settings > Sync** |
| [MCP clients](#the-mcp-server) | nowhere: it listens on `127.0.0.1` | No | **Settings > MCP** |
| [Account and Team Library](#your-account-and-the-team-library) | `account.tablepro.app`, `api.tablepro.app` | Only after you sign in, or an update finds a license key | **Sign Out** in **Settings > Account** |
| [Your databases](#your-database-connections) | the hosts you type into the connection form | Only what you connect to | Do not connect |
| Crash reports | Nowhere. The crash reporter inside PostHog's library is turned off. | - | - |

## Usage data

Events go to PostHog, the product analytics service, at `https://eu.i.posthog.com` in the EU. Nothing asks first: `app_opened` goes about ten seconds after launch.

| Event | Sent | Properties |
| --- | --- | --- |
| `app_opened` | Once per local day | `database_types` and `connection_count` of the connections open at that moment, such as `PostgreSQL` |
| `connection_attempted`, `connection_succeeded`, `first_query_executed` | Once per install | `database_type`, such as `MySQL` or `SQL Server` |
| `feature_gate_shown` | Once per paid feature per launch, when its overlay or dialog shows | `feature`, such as `query_insights`, and `reason`: `signed_out`, `not_included`, `expired`, or `refresh_failed` |
| `upgrade_clicked` | On a click through to the pricing page or the portal's billing | `source`, where the click came from: `app-support`, `app-settings`, or `app-gate-` and the feature |
| `signed_in` | On each sign-in | `method`: `interactive`, `license_key` for **Use License Key…**, or `migration` for the first launch's key exchange |
| `signed_out` | When you click **Sign Out** | none |

A Mac updated from a version before TablePro accounts keeps its first-connection dates and does not send those three events again.

Before you sign in, events carry a random ID that the library makes on the Mac, and PostHog builds no person profile from it. After sign-in they carry your account ID, and the profile holds `app_version`, `os_version`, `architecture` (`arm64` or `x86_64`), and `locale`, the app's language setting. That links an install to its sign-ins and purchases. **Sign Out** sends `signed_out`, then starts a new random ID. A sign-in the server ended, such as a removed device, starts a new ID without sending anything.

PostHog's library, posthog-ios, adds to every event the Mac's model, screen size, time zone and language, whether it is on Wi-Fi, the app's version, build and bundle ID, the macOS version, the library's version, and a random session ID. PostHog sees the IP address of each request and derives an approximate location from it, such as the country and city. While the switch is on, the library also fetches its settings from `eu-assets.i.posthog.com` and feature flags from `eu.i.posthog.com`.

No query text. No hostnames, ports, database names, or usernames. No email address, no file paths, no connection names. No machine ID, no license state, and no update settings either.

Each event is sent as it is captured. One still waiting for the network sits in a file under `~/Library/Application Support/com.TablePro`, with the random ID and the library's settings.

**Share usage data** in **Settings > General** is on by default. With it off, the app sends PostHog nothing, not even the sign-in that links an account. A launch with it off never starts the library, and a build without a PostHog project key, such as one built from source, never sends usage data at all.

Versions before TablePro accounts send a heartbeat instead, under the same switch: one `POST` to `https://api.tablepro.app/v1/analytics` ten seconds after launch and every 24 hours, carrying a SHA-256 of the Mac's hardware UUID, the app and macOS versions, the architecture and language, the open connections' types and count, whether a license key is stored, when you first tried and first managed to connect, and the update settings. The server forwards it to PostHog as a `heartbeat` event about that machine, with Cloudflare's country and without the IP address, the license key, or the update settings. The iPhone and iPad app sends a heartbeat of the same kind, with `platform` `ios`, and only after you choose **Share Usage Data**; see [iPhone and iPad](/ios#privacy).

## AI providers

Nothing reaches a model until you add a provider, and a fresh install has none: with none configured, every AI path returns before it builds a request. **Enable AI Features** in **Settings > AI** is on out of the box, but it gates an empty tab.

One provider is marked active and answers inline suggestions and the editor actions; the chat panel's own model picker can send a turn to any other provider you configured. Requests go to that provider's endpoint. The presets are `api.anthropic.com`, `api.openai.com`, `generativelanguage.googleapis.com`, `api.x.ai`, `openrouter.ai`, `router.requesty.ai`, `api.cursor.com` and `opencode.ai`, plus `http://localhost:11434` for Ollama and `http://localhost:8080` for llama.cpp and MLX, which keeps their traffic on the machine. Every endpoint field is editable, and a custom provider goes wherever you point it.

A chat turn carries:

- The database type and the name of the database you are connected to.
- The schema, while **Include database schema** is on (the default): table names, estimated row counts, column names and types, primary key and NOT NULL flags, DEFAULT values, and foreign keys, for up to **Max schema tables** tables (20 by default). With more tables than that, the ones your question and current query use come first, and the rest are sent as a count, not by name.
- The query in the current tab, while **Include current query** is on (the default), truncated at 2,000 characters.
- Result rows, only if you turn on **Include query results**, which is off by default. It attaches the first 10 rows of the current result, each value cut at 200 characters.
- The connection's [AI Rules](/features/ai-assistant#per-connection-ai-rules) text, if you wrote any.
- Any images you paste into the composer, and the conversation so far.

In Edit and Agent modes the model calls `execute_query` itself, and the rows it gets back become part of the conversation, so they go to the provider on the next turn. Those results are capped by the row limits in **Settings > MCP**: 500 rows by default, 10,000 at most.

Per connection, the **AI Policy** picker in the connection form's Options section takes **Use Default**, **Always Allow**, **Ask Each Time**, or **Never**. The app-wide default is **Ask Each Time**, which asks once per connection per chat session before the first send. **Never** blocks the chat panel and external AI tool calls against that connection.

<Warning>
**Ask Each Time** gates the chat panel only. Inline suggestions check the policy for **Never** and nothing else, so with **Enable inline suggestions while typing** on, the text before your cursor, the whole query, and the schema go to the provider after every typing pause with no prompt. That toggle is off by default.
</Warning>

Provider API keys live in the keychain, never in `connections.json` and never in a CloudKit record. The provider list itself (type, name, endpoint, model) rides along with the Settings category of iCloud sync when sync is on.

Signing in to ChatGPT opens a second local listener on port 1455 for the OAuth redirect. It runs only during that sign-in and closes after it.

Two provider paths run a program rather than call an endpoint. **Claude Agent** runs the `claude` command line tool, which talks to Anthropic under your own subscription. **GitHub Copilot** downloads its language server from `registry.npmjs.org` and starts it on first use or when **Settings > AI** lists the provider, never at launch. It stops when AI is turned off or the Copilot provider is removed. Its provider sheet has **Send telemetry to GitHub**, which is on when you add the provider. Turning it off sets the language server's telemetry level to `off`.

## iCloud sync

Off by default, and it needs a Starter or Team plan. When it is on, records go to the CloudKit container `iCloud.com.TablePro`, into the private database of your own iCloud account, in the Production environment.

Eight record types sync: `Connection`, `ConnectionGroup`, `ConnectionTag`, `AppSettings`, `SQLFavorite`, `SQLFavoriteFolder`, `FavoriteTable`, and `SSHProfile`. A connection record carries host, port, username, database, and SSH and SSL settings. Sync runs on launch, when you switch back to the app, and about two seconds after you change something synced.

Passwords are not one of those record types. The **Passwords** toggle nested under Connections instead marks keychain items as synchronizable, so Apple's iCloud Keychain carries them end to end encrypted. It is off by default, and it applies to items written after you turn it on.

<Warning>
That flag is set on every keychain item the app writes, not only connection passwords: AI provider keys and a license key an older version stored go through the same helper. MCP tokens, Google sign-in refresh tokens and your TablePro account's sign-in do not; their stores always write device-only items.
</Warning>

With password sync off, secrets are written `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, which keeps them on that one Mac. Query history, the activity log, the execution log, tab state, MCP settings, and the sync settings themselves are never synced. Individual connections can be marked **Local only**. Full detail in [iCloud Sync](/features/icloud-sync).

## The MCP server

The server listens on `127.0.0.1` and nothing else. Its listener sets `requiredLocalEndpoint` to the IPv4 loopback address, so there is no remote mode and no setting that opens it to your network. Default port 23508.

It is off by default, and nothing starts it while **Enable MCP Server** is off: not the bundled bridge, not the pairing flow, not a `tablepro://integrations/start-mcp` link. What a paired client can reach is real data, so four gates stack:

1. A token on every request. One that arrives without an `Authorization` header is refused, from your own Mac too, and no setting changes that.
2. The token's scope and its connection allowlist.
3. The connection's **External Clients** level: **Blocked**, **Read Only** (the default for a new connection), or **Read & Write**. The effective permission is the lower of that and the token's scope.
4. The connection's **AI Policy** of **Never**, its [Safe Mode](/features/safe-mode) level, and the **Approval** setting under **Settings > MCP**, which decides how often a client is asked before it reaches a connection.

Loopback-only describes where the server binds, not everything that can reach it. The server returns CORS headers for two remote origins, `claude.ai` and `app.cursor.com`, so a page you have open there can call your local server from your own browser. The four gates above are what stands between such a call and your data, and the first one means a page without a token gets nothing.

Every call is written to the local activity log with the token behind it, statements as SHA-256 digests. See [Tokens](/developers/tokens) for the whole model.

## Update checks

Sparkle fetches `https://updates.tablepro.app/appcast.xml` once a day, and once for every **Check for Updates…** you press. It is a plain `GET` with no query parameters: system profiling is off, so nothing about your Mac rides along. The user agent names the app and its version, and GitHub Pages, which hosts the feed, sees your IP address as it would for any web request. **Get beta updates** sends nothing extra: the one feed lists stable releases and betas, and your Mac picks between them. Versions without **Get beta updates** fetch `https://raw.githubusercontent.com/TableProApp/TablePro/main/appcast.xml` instead.

Updates download from the GitHub release named in the feed. Sparkle checks the feed's EdDSA signature, and each build's, against the public key inside the app, and refuses either one that does not match before it unpacks anything.

**Automatically check for updates** in **Settings > General** is on by default. With it off, **Check for Updates…** in the same section is the only thing that reaches the feed.

**Download and install updates automatically** is also on by default, so a new build downloads without being accepted first and installs when TablePro quits. The download is the same signed archive from the same GitHub release, and nothing is sent to fetch it. Turn it off to be asked each time.

## The plugin catalog

At launch the app asks for `https://updates.tablepro.app/plugins/v3.json`, and its HTTP cache answers without a request while the last response is under ten minutes old. It asks the server again before it reports a plugin missing, and when it repairs a plugin that a newer app version rejected. The request adds no header of its own; GitHub Pages sees the IP address and the user agent URLSession sends. The response is cached on disk.

Installing a plugin downloads its ZIP over HTTPS from the URL in that catalog and checks it against the SHA-256 the catalog declares.

There is no setting that turns the catalog fetch off.

## Your account and the Team Library

With no account signed in and no license key on the Mac, the app never calls the account server.

**Sign In** opens `https://account.tablepro.app/oauth/authorize` in a browser sheet, carrying the Mac's name, the app version and the macOS version, so the confirmation screen can name the Mac. The code it returns is exchanged at `/oauth/token` on the same host. The app then registers the Mac with `POST https://api.tablepro.app/v2/devices`: its machine ID (a SHA-256 of the hardware UUID, or of a random ID stored where that cannot be read), the platform, the Mac's name, the app version and the macOS version. It fetches the signed copy of your plan from `/v2/devices/{id}/entitlement` with the app and macOS versions, on the schedule in [Licensing](/features/licensing#offline-use). Opening **Settings > Account** reads your account, teams and licenses from `/v2/me` and your devices from `/v2/devices`. **Remove** on a device sends `DELETE /v2/devices/{id}`. **Sign Out** revokes the sign-in at `/oauth/revoke`.

The first launch that finds a license key from an older version sends it once to `/oauth/token`, with the machine ID, the Mac's name, the platform and both versions, and deletes the key from the Mac when the exchange works. **Use License Key…** sends the same fields.

<Info>
The Mac's name is the only field in any request that tends to hold a person's name, because macOS builds it from the account name. It goes to the account server, never to PostHog.
</Info>

The server keeps each device with its machine ID, name, platform, versions, and when it last checked in. The account's audit log records each sign-in and new device with the IP address and browser it came from.

Team Library needs a seat on a team, and only owners and admins publish to it. **Share > Publish to Team Library…** and **Publish Saved Queries to Team…** send the connection definitions and the saved query text to `/v2/teams/{id}/library/changes`; the publish path builds the export envelope without credentials, so passwords, key passphrases, and TOTP secrets are not in it, and the server refuses any field named like one. Each member's app pulls changes from the same path at launch, every 15 minutes, and after each publish, and every one of those syncs starts with `GET /v2/me` for your teams and roles.

Versions before TablePro accounts call `https://api.tablepro.app/v1/license` only after you activate a key. Activation and the check every 7 days send the license key, the machine ID, the Mac's name, the app version, and the OS version; deactivation sends the key and the machine ID. Their Team Library goes through `/v1/license/library`, pulled weekly and right after a publish.

## Crash reports

There are none. PostHog's library, which the app ships for usage data, compiles a crash reporter that the app leaves turned off, so nothing uploads a crash log, a stack trace, or a diagnostic file. Logging goes through OSLog and stays in the system log store on your Mac.

## Your database connections

The largest thing leaving your Mac is the traffic you asked for: the connection to your own server, plus whatever hops you configured, such as an SSH tunnel, a Cloudflare tunnel, a SOCKS proxy, or Cloud SQL Proxy. Cloud drivers reach their vendor's endpoint by design, so BigQuery talks to `bigquery.googleapis.com`, Spanner to `spanner.googleapis.com`, DynamoDB to AWS, and Microsoft Entra authentication to `login.microsoftonline.com`.

Two helpers download on first use, and each is verified before it runs: the Cloud SQL Proxy binary from `storage.googleapis.com` against a pinned SHA-256, and the Copilot language server at a pinned version, against pinned SHA-256 digests of the archive and the binary.

## What stays local

The execution log records every authorization decision the app makes, from the UI, an MCP client, the AI assistant, the import pipeline, or background maintenance. Each record holds a sequence number, a timestamp, the connection ID, the operation kind, which of those five callers asked, allowed or denied, whether it counted as a write, a SHA-256 digest of the statement, and the previous record's hash. The statement text is never stored, and neither is a caller-supplied label such as an MCP client name or an AI session ID, only the channel it came through.

The hash chain is tamper evident, not tamper proof: anyone who can write the file can recompute every hash after the record they changed. It is a JSON file in Application Support, no sync record type covers it, and no code path uploads it.

The table load history records how long each table load took, so a slowdown can be looked at after it happened rather than only while it is happening. One line per load, holding a timestamp, the app version and build, the macOS version, what started the load, the database type, whether the connection went through SSH, how long each phase took (schema, driver fetch, result conversion, grid reload, and the main run loop after it), how the load ended, any anomalies it reported, and four size ranges: rows, columns, result size, and open tabs. Sizes are ranges such as `101-1000` and `1-10MB`, never exact counts.

Nothing identifying is in it: no query text, no rows, no database, schema or table names, no hostnames, ports or usernames, no connection names or IDs, no file paths, no error messages. It is a `.jsonl` file in Application Support, readable only by you, capped at 7 days and at 10,000 records or 5 MB, whichever comes first. No sync record type covers it and no code path uploads it. Delete the file to clear it.

### Where it lives on disk

Every path here is under `~/Library/Application Support/TablePro/` unless it says otherwise.

| Path | What it holds |
| --- | --- |
| `connections.json` | Connection definitions: host, port, username, database, SSH and SSL settings. No passwords. |
| `connections.json.hmac` | The integrity tag for `connections.json`. |
| `known_hosts` | SSH host keys you accepted. |
| `query_history.db` | The statements you ran, as text, with a full-text index. Parameter values are never recorded. |
| `sql_favorites.db` | Saved queries and their folders. |
| `ai_chats/` | One JSON file per AI conversation, including the context attached to each turn. |
| `AIChatImages/` | Images pasted into chat. |
| `ExecutionAudit.json` | The execution log described in this section. |
| `TableLoadHistory.jsonl` | The table load history described in this section, 7 days. Mode `0600`. |
| `mcp-audit.db` | The MCP activity log, 90 days, statements as digests. Mode `0600` inside a `0700` directory. |
| `mcp-handshake.json` | The bound port and the bridge token, mode `0600`. |
| `TabState/`, `RecentlyClosedTabs/` | Open and recently closed tabs, including their query text. |
| `FilterState/`, `ColumnLayout/` | Per-table filters and column widths. |
| `LastSession.json`, `LastOpenConnections.json` | What to reopen for **Reopen Last Session**, and which of those connections dial on their own. |
| `Plugins/` | Plugins you installed yourself. |
| `Registry/URLCache/` | The cached plugin catalog. |
| `TeamLibrary/` | One file per team: the cached Team Library, the sync position, and changes and conflicts not sent yet. |
| `team_library.json` | An older version's cached Team Library, removed once every team has synced. |
| `Account/entitlement.jwt` | The signed copy of your plan, or the offline file you imported. |
| `linked_sql_index.db` | File metadata for linked SQL folders. |
| `~/Library/Preferences/com.TablePro.plist` | Settings, and until its key is exchanged, the signed license an older version stored, which carries the email on the license. |
| `~/Library/Application Support/com.TablePro/` | PostHog's random ID, settings, and events not sent yet. |

## Passwords and secrets

Secrets live in the macOS keychain, under the `com.TablePro` service and in the data protection keychain: connection passwords, SSH passwords, key passphrases, SSL client key passphrases, TOTP secrets, plugin secure fields, AI provider keys, and a license key an older version stored, until it is exchanged. Your TablePro account's sign-in is a refresh token kept only on this Mac, never in iCloud Keychain; the short-lived access token stays in memory. Google sign-in refresh tokens for BigQuery and Spanner are kept in the same keychain under `com.TablePro.GoogleOAuth`, one per OAuth client ID. MCP tokens are the exception, stored as a salted SHA-256 hash; the plaintext is shown once at creation and never written down.

A connection can name a [password source](/features/connection-sharing#password-sources) instead of using the keychain: a file, an environment variable, a shell command, 1Password, HashiCorp Vault, AWS Secrets Manager, or a Vault database role. Those resolve at connect time, on your machine, and are never synced, since a path or a command belongs to one Mac. A Vault database role sends your Vault token to the address it names, and the database password it gets back stays in memory.

<Warning>
The `command`, `onePassword`, `vault`, and `awsSecretsManager` kinds run a program on your Mac, and `vaultDatabaseRole` sends a Vault token where it says. The app keeps a signature over `connections.json` for that reason: if the file changed outside the app, password sources do not run and the connection reports why. Open the connection and save it from TablePro to accept the change.
</Warning>
