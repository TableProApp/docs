`open "mysql://…"` goes to whichever app claims the `mysql://` scheme, and with another database
client installed that may not be TablePro. Name TablePro instead, either by bundle identifier or
through the `tablepro` command:

```bash
open -b com.TablePro "mysql://root@127.0.0.1:3306/shop"
tablepro "postgresql://user:pass@127.0.0.1:5432/app?table=orders"
```

Any [connection URL](/connections/urls) works, including its query parameters. TablePro uses a saved
connection when one matches on type, host, port, database and user; otherwise the session is
temporary and never written to disk. Running `tablepro` with no argument opens the app and nothing else.

<Info>
TablePro for Linux ships the same command with the app. See [Command line](/linux/command-line).
</Info>

## Add the tablepro command to your PATH

The command ships inside the app at `TablePro.app/Contents/SharedSupport/bin/tablepro` and works
with the copy it ships in: files and links open there, and a command that needs TablePro running
starts that copy. A copy already running from another folder receives them instead. Link the command
into `/usr/local/bin` once:

```bash
sudo mkdir -p /usr/local/bin && sudo rm -f /usr/local/bin/tablepro && sudo ln -s /Applications/TablePro.app/Contents/SharedSupport/bin/tablepro /usr/local/bin/tablepro
```

`sudo` asks for your password in Terminal. TablePro itself never writes outside its own folders and
never asks for an administrator password. **Settings > General > Command Line** prints the same line
with the path of the copy you are running, and reads **Linked** once the link is in place. Any other
directory on your `PATH` works too, and one you own needs no `sudo`.

A copy opened from the mounted disk image, or one macOS still runs from where it was downloaded (App
Translocation), sits on a read-only volume. Settings shows no line for it and asks you to move
TablePro to Applications. Move it, open it from there, and the line appears.

To remove it, run `sudo rm /usr/local/bin/tablepro`. The link follows the app, so updating TablePro
updates the command; move the app and the link needs making again.

`tablepro --version` prints the version of the app the command ships in. `tablepro --help` lists the
commands, and `tablepro help query` or `tablepro query --help` explains one.

## Open a file

Files route the same way, whether double-clicked in Finder or passed on the command line:

```bash
tablepro schema.sql
tablepro app.db
```

- `.sql`, `.psql` and `.pgsql` open in a query tab on the current connection. A window already
  holding that file comes to front. With no connection open, the file waits until you connect.
- Database files open a connection to the file itself and save nothing: `.db`, `.db3`, `.s3db`,
  `.sl3`, `.sqlite`, `.sqlite3` and `.sqlitedb` open with SQLite, `.duckdb` and `.ddb` with the
  DuckDB plugin. A window already connected to that file comes to front instead of a second one
  opening.

`tablepro <file>` is short for `tablepro open <file>`. A word that is neither an existing file nor a
URL opens nothing and exits 2, so `tablepro qeury` fails instead of starting the app. A file named
like a command, such as `tables`, opens with `./tables` or `tablepro open tables`.

## Run a query

```bash
tablepro query --connection Staging --format csv "SELECT id, email FROM users LIMIT 5"
tablepro query -c Staging -f report.sql > report.csv
echo "SELECT count(*) FROM orders" | tablepro query -c Staging --format json
```

`--connection` takes a saved connection's name or its id, and `tablepro connections` lists both. The
SQL comes from the argument, from `-f <file>`, or from standard input, and `-f -` reads standard
input even at a terminal, until `Ctrl+D`. Rows go to standard output, messages and errors to
standard error.

SQL that starts with a dash, such as a leading `--` comment, goes after `--`, which ends the options:

```bash
tablepro query -c Staging -- "-- weekly report
SELECT count(*) FROM orders"
```

| Option | |
|---|---|
| `--database`, `--schema` | Where the statement runs. Without them, the connection's current database and schema |
| `--format` | `csv`, `tsv`, `json`, `jsonl` or `table`. `table` on a terminal, `csv` into a pipe or a file |
| `--limit` | Rows to return. Defaults to **Default row limit** under **Settings > MCP**, 500, and stops at **Maximum row limit** |
| `--timeout` | Seconds the statement may run, 1 to 300. Defaults to **Query timeout** under **Settings > MCP**, 30 |
| `--read-only` | Refuse any statement that is not a read, even on a connection set to **Read & Write** |

A result cut short by `--limit` says so on standard error.

### What a query may do

A query clears the same gates as any [MCP client](/features/mcp#connection-access), and so does
every other command that names a connection:

- The connection's **External Clients** level: **Blocked** hides it, **Read Only** refuses writes.
- A connection whose AI policy is **Never** is hidden as well. A hidden connection reads as unknown,
  by name or by id, and the command exits 2.
- The first query on each connection asks you, as often as **Approval** under **Settings > MCP** says.
- [Safe Mode](/features/safe-mode) confirms or authenticates writes on your Mac.
- `DROP` and `TRUNCATE` are refused. Run them in TablePro.
- One statement per run. A SQL Server script runs batch by batch at its `GO` lines and prints
  every result set, separated by a blank line, or in JSON as one array per result set.

Every statement goes to the execution audit log, and to the [history drawer](/features/query-history#sources)
under **Command Line**.

## Browse a schema

```bash
tablepro connections --format json
tablepro databases -c Staging
tablepro tables -c Staging --database app --schema public
tablepro describe -c Staging --schema public orders
tablepro describe -c Staging --ddl orders
```

## Export a table

```bash
tablepro export -c Staging --format csv orders > orders.csv
tablepro export -c Staging --format sql --limit 5000 orders > orders.sql
```

`--format` is `csv`, `json` or `sql`, and `sql` writes `INSERT` statements in the connection's own
quoting. Each table stops at **Default row limit** under **Settings > MCP**, 500 unless you change
it, and `--limit` raises that as far as **Maximum row limit**. A table cut short says so on standard
error. For every row, use [Export](/features/import-export) in the app.

A table name takes letters, digits and underscores, optionally as `schema.table`. For any other
name, run `tablepro query` with `--format csv` or `--format json`.

## Pair the command

The command reaches TablePro through its MCP server, so turn on **Enable MCP Server** under
**Settings > MCP** first. With it off, every command that reads from TablePro exits 3. When TablePro
is not running, the command starts its own copy in the background, with no window.

<Steps>
  <Step title="Run tablepro pair in Terminal">
    Any other command that reads from TablePro starts the same pairing the first time. TablePro asks
    **Allow tablepro command to access TablePro?**
  </Step>
  <Step title="Choose what the command may do">
    The sheet starts at **Read Only**. Pick **Read & Write** if your scripts write, and limit the
    connections or set an expiry if you want.
  </Step>
  <Step title="Approve">
    Your browser opens a page saying the command is paired. Close it. A command you ran continues.
  </Step>
</Steps>

The token lives in your login Keychain. Revoke it under **Settings > MCP** and the next run exits 3;
the run after that asks to pair again. A run whose standard error is not a terminal, such as a cron
job, exits 3 instead of opening the sheet. `tablepro pair` replaces the stored token with a new one;
run `tablepro unpair` first to revoke the old one.

### Check or remove the pairing

`tablepro status` shows the path and version of the copy the command belongs to, whether TablePro is
running, whether the MCP server is on, and whether the command is paired. It never starts TablePro
and never asks to pair. It exits 0 when a command can run now, 1 when TablePro is not running or
cannot be reached, and 3 when the server is off or the command is not paired.

`tablepro unpair` revokes the token in TablePro, then deletes it from the Keychain. When TablePro
cannot be reached, it deletes only the Keychain copy and says so. The token then stays active under
**Settings > MCP > Authentication** until you revoke it there.

## Shell completion

`tablepro completion zsh`, `bash` or `fish` prints a script that completes commands, options and
`--format` values. Connection names do not complete. Save the script where your shell loads it:

<CodeGroup>

```bash zsh
mkdir -p ~/.zsh/completion
tablepro completion zsh > ~/.zsh/completion/_tablepro
```

```bash bash
mkdir -p ~/.bash_completions
tablepro completion bash > ~/.bash_completions/tablepro.bash
echo 'source ~/.bash_completions/tablepro.bash' >> ~/.bash_profile
```

```bash fish
tablepro completion fish > ~/.config/fish/completions/tablepro.fish
```

</CodeGroup>

zsh also needs the folder on its function path. Add these lines to `~/.zshrc` once, then open a new
shell:

```bash
fpath=(~/.zsh/completion $fpath)
autoload -U compinit && compinit
```

Run the command again after an update that adds commands.

## Trusting a link

The first time a link connects, TablePro asks: **Open External Database Connection?**, showing the
host, user and database. This is what stops a web page from opening a connection behind your back.

For a database on your own machine (`localhost`, `127.0.0.1`, `::1`, or any `127.x.x.x` address) the
alert adds **Always Allow**. Choose it and that database stops asking, which is what makes
[`ddev tablepro`](/integrations/ddev) a one-step command. Trust is keyed on database type, host,
database name, user and the URL's `name` parameter, not the port, so a tool that picks a new port on
each start stays trusted.

<Note>
A link to a remote host asks every time. Only a database on this machine can be trusted.
</Note>

**Settings > General > Trusted Links** lists what you have trusted, with **Forget** per entry and
**Forget All**. Two things still prompt even on a trusted connection: a link carrying a filter
(`?query=`, `?condition=` or `?raw=`) confirms the filter, and a connection with a pre-connect script
shows the script.
