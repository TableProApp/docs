Open files and connection links in the app with `tablepro`, or run a command to print database results in your shell. Queries, browsing and exports use the app's MCP server and its access rules.

For Linux, see [Command line](/linux/command-line).

## Install

With the app in `/Applications`, run this line in Terminal:

```bash
sudo mkdir -p '/usr/local/bin' && sudo rm -f '/usr/local/bin/tablepro' && sudo ln -s '/Applications/TablePro.app/Contents/SharedSupport/bin/tablepro' '/usr/local/bin/tablepro'
```

For a different location, copy the line from **Settings > General > Command Line**. It links `/usr/local/bin/tablepro` to the command inside that copy of the app. Enter your administrator password in Terminal when `sudo` asks.

A copy on a read-only volume, including a mounted disk image or an App Translocation location, offers no install line. Move the app to Applications and open it there first.

App updates also update the command. If you move the app, recreate the link. To remove the link:

```bash
sudo rm /usr/local/bin/tablepro
```

Use `tablepro --help` to list commands, `tablepro help query` for a command's options, and `tablepro --version` for the bundled app's version.

## Open files and links

```bash
tablepro
tablepro schema.sql
tablepro app.sqlite3
tablepro "postgresql://ada@127.0.0.1:5432/shop?table=orders"
```

With no arguments, open the app. Files and links go to the copy the command ships in, or to a copy already running.

SQL files (`.sql`, `.psql`, `.pgsql`) open in an editor tab without running. With no connection open, they wait until you connect. SQLite and DuckDB files open a temporary connection. An already open file brings its window forward.

Use any [connection URL](/connections/urls) or [tablepro link](/developers/url-scheme). A matching saved connection is reused; otherwise the session is temporary. See [Trusting a link](#trusting-a-link) for the consent prompt.

`tablepro open <target>` is the explicit form. Use `tablepro open tables` or `tablepro ./tables` for an existing file named like a command. A target must be an existing file or a URL with a scheme; a typo such as `tablepro qeury` exits 2.

## Run a query

Turn on **Settings > MCP > Enable MCP Server** and [pair the command](#status-and-pairing) before running scripts.

```bash
tablepro query -c Staging "SELECT id, email FROM users LIMIT 5"
tablepro query -c Staging -f report.sql --format csv > report.csv
printf '%s\n' 'SELECT count(*) FROM orders' | tablepro query -c Staging --format json
```

Choose one SQL source: an argument, `-f` (`--file`), or piped input. `-f -` also reads from a terminal until `Ctrl+D`. Put SQL that starts with a dash after `--`:

```bash
tablepro query -c Staging -- "-- weekly report
SELECT count(*) FROM orders"
```

| Option | Use |
|---|---|
| `-c`, `--connection` | Saved connection name or id; find it with the [browse commands](#browse-a-connection) |
| `--database`, `--schema` | Override the connection's current database or schema |
| `--format` | Choose an [output format](#output-formats) |
| `--limit` | Set the returned row count, within **Maximum row limit** in **Settings > MCP** |
| `--timeout` | Set the statement timeout in seconds |
| `--read-only` | Refuse any statement that is not a read |

Without a limit or timeout, the [MCP defaults](/features/mcp#server-configuration) apply. A result cut short prints a message on standard error.

## Export

```bash
tablepro export -c Staging --format csv orders > orders.csv
tablepro export -c Staging --schema public --format sql --limit 5000 orders users > shop.sql
```

Choose `csv`, `json` or `sql`; `--format` is required. SQL output contains `INSERT` statements in the engine's dialect. Use `--database` and `--schema` to select where the tables live.

The [query row limit](#run-a-query) also applies to each exported table. `--limit` overrides it, and standard error names any table cut short. For a full export, use [Import & Export](/features/import-export) in the app.

Table names accept letters, digits and underscores, with dots between parts such as `public.orders`. For other names, quote the name in SQL and use `query --format csv` or `query --format json`.

## Status and pairing

`tablepro status` checks the app, MCP server and pairing without starting the app or asking for approval. Add `--format json` for scripts. It exits 0 when ready, 1 when the app cannot be reached, and 3 when the server is off or the command is not paired.

Other commands that need the server start the app if needed. The MCP server must already be enabled in Settings; when it is enabled but fails to start, the command says so and exits 1.

<Steps>
  <Step title="Start pairing">
    Run `tablepro pair` in Terminal. A query or browse command also starts pairing when no token is stored and standard error is a terminal.
  </Step>
  <Step title="Approve in TablePro">
    The sheet starts at **Read Only**. Choose **Read & Write** for scripts that change data. Select the allowed connections and expiry, then click **Approve**.
  </Step>
  <Step title="Return to Terminal">
    Close the browser confirmation tab. The token is stored in your login Keychain. If a command started pairing, it continues.
  </Step>
</Steps>

An unattended command with no token exits 3. A rejected or expired token is removed and that run exits 3; run `tablepro pair` again. Pairing again stores a replacement and asks the server to revoke the previous token. If that fails, the command prints a warning; revoke the old token in Settings.

When TablePro cannot issue the token after you approve, the browser tab says it could not finish pairing, TablePro shows why, and the command exits 1. Run `tablepro pair` again once the cause is fixed.

`tablepro unpair` revokes the token and removes its Keychain copy. If the server cannot be reached, only the local copy is removed; revoke the remaining token in **Settings > MCP > Authentication**. If the server reports that it could not save the revocation, the local token stays for another attempt. These failures exit 1.

## Shell completion

Generate the script for your shell. It completes commands, options and format names, but does not look up connection names.

<CodeGroup>
```bash zsh
mkdir -p ~/.zsh/completion
tablepro completion zsh > ~/.zsh/completion/_tablepro
```

```bash bash
mkdir -p ~/.bash_completions
tablepro completion bash > ~/.bash_completions/tablepro.bash
echo 'source ~/.bash_completions/tablepro.bash' >> ~/.bash_profile
```

```bash fish
mkdir -p ~/.config/fish/completions
tablepro completion fish > ~/.config/fish/completions/tablepro.fish
```
</CodeGroup>

For zsh, add these lines to `~/.zshrc` once:

```bash
fpath=(~/.zsh/completion $fpath)
autoload -U compinit && compinit
```

Open a new shell. Generate the script again after an update adds commands or options.

## What a query may do

The command follows the [MCP connection access rules](/features/mcp#connection-access):

- **Blocked** connections, an AI policy of **Never**, and connections outside the token's allowlist are hidden. Naming one exits 2.
- Writes need both a **Read & Write** token and **Read & Write** external access. `--read-only` still refuses them.
- **Approval** in **Settings > MCP** controls connection approval. [Safe Mode](/features/safe-mode) also applies to writes.
- Destructive statements such as `DROP`, `TRUNCATE`, `ALTER ... DROP` and `DELETE` without `WHERE` are refused. Run them in the app. Statements that access files or run server-side code are also refused.

Send one statement per query. SQL Server also accepts a script split at `GO` lines and returns each result set. Executed queries enter the audit log and [query history](/features/query-history#sources).

## Trusting a link

A database link asks **Open External Database Connection?** before connecting. Check the host, user and database before approving.

For a local connection without SSH or a filter, **Always Allow** remembers the database type, host, database, user and URL `name`. Local hosts include `localhost`, `::1` and `127.x.x.x`. A local socket grant also includes its path. The port is excluded, so a development server may change ports without asking again. Remote hosts and SSH links ask every time.
