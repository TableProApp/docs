---
title: Data Masking
description: Hide column values such as emails and card numbers in the grid, exports, shared links, the AI assistant and MCP, on Mac, Linux and Windows
---

Turn on masking before a screen share, a pairing session or a recorded demo on production data. A masked column still shows a value in every row, so you see that a column holds an email, or that two rows share one, without seeing the address. Masking is free on every plan and needs no account.

## Add a rule

Rules belong to a connection and live in its settings:

| App | Where the rules are |
|-----|---------------------|
| Mac | The [connection form](/connections/connection-form#options), **Options** tab, **Masking** |
| Linux | The [connect dialog](/linux/connect#options), **Data Masking** group |
| Windows | **Edit connection...** in the **Database** menu, or **New connection...** in the **File** menu, then **Options**, **Data masking** |

Click **Add Rule**, or **Add rule** on Windows, then set three things:

| Part | What it takes |
|------|---------------|
| Column or type | **Column** matches a column by name, **Type** matches its declared type. The Mac labels this **Match**, Linux **Applies To** |
| Pattern | `table.column` or `column`. `*` stands for any run of characters and `?` for one. Case does not matter |
| Mask | How the value shows, from the table in [Masks](#masks). Linux labels this **Style** |

Some patterns:

| Pattern | Masks |
|---------|-------|
| `*.email` | Every column named `email`, in any table |
| `users.ssn` | `ssn` in the `users` table |
| `*password*` | Any column whose name contains `password` |
| `inet` in a **Type** rule | Every column declared as `inet` |

When two rules match one column, the first in the list wins. Saving the connection masks the rows already on screen, without reconnecting. On the Mac, rules sync through [iCloud](/features/icloud-sync) and travel with a connection published to the [Team Catalog](/features/team). Linux and Windows keep them with the connection on that computer.

## Masks

| Mask | `jane.doe@example.com` shows as |
|------|----------------------------------|
| **Full** | `••••` |
| **Last 4 Characters** | `••••.com` |
| **Email** | `j•••@example.com` |
| **Stable Hash** | 12 hex characters, the same for equal values |
| **NULL** | `NULL` |

Windows writes two of them in sentence case: **Last 4 characters** and **Stable hash**. All three apps give the same output for the same value.

A value that is already NULL stays NULL. **Last 4 Characters** shows `••••` for a value of four characters or fewer, and **Email** shows `••••` for a value with no `@`. A **Stable Hash** stays the same until TablePro quits, so it matches equal values across the grid, an export and an MCP result from one session. Another launch, or another computer, gives other hashes.

## Where values are masked

One rule covers the grid and every path a value takes out of the app:

| Where | Mac | Linux | Windows |
|-------|-----|-------|---------|
| Data grid and query results | Yes | Yes | Yes |
| Copy | Yes | Yes | Yes |
| Export, every format | Yes | Yes | Yes |
| [Shared links](/features/shared-links#sensitive-data) | Yes | Yes | Yes |
| AI assistant | The results it reads and the queries it runs | Reads no rows. **Fix with AI** sends the error code without the server's message | No assistant |
| MCP clients | Every tool that returns rows | Query results, browses and exports | No MCP server |
| Database dumps and [backups](/features/backup-restore) | No. **File > Backup Dump…** writes the stored values | No. A database dump with data writes the stored values | No dumps |

A masked column's header says so: an eye-slash icon on the Mac and on Windows, where its tooltip reads "Masked by a masking rule", and `(masked)` after the name on Linux.

On the Mac, masking also covers the row inspector, charts, **Copy As**, **Export Results**, AppleScript and Shortcuts results, the referenced-row preview of a foreign key, Server Dashboard tiles and the [Routine Debugger](/features/routine-debugger) result grid.

A query result has no source table for most engines, so in the grid a `table.column` rule matches a query result by its column name alone. `users.ssn` then also masks an `ssn` column a query reads from another table.

## Masking for AI and scripts

Results for MCP clients, the AI assistant, Claude Agent, AppleScript and Shortcuts are masked by the table column each result column reads, as well as by its name. So are shared links from all three apps, and MCP results on Linux. With the Mac's PostgreSQL, MySQL, MariaDB and local SQLite drivers, `SELECT email AS contact FROM users` comes back masked by a `*.email` rule.

On a connection with at least one rule, a column that reads no column of a user table comes back as `••••`, whatever its name. The result's status message names the columns masked this way, and the share sheet marks them "Masked because TablePro cannot tell which table column this comes from." That covers:

- An expression or an aggregate, such as `lower(email)` or `count(*)`.
- A system table or catalog, such as `pg_stat_activity`, in a query, a browse or an export. Schema lookups such as `describe_table` still return the structure.
- Every column of a statement the driver does not trust: a subquery, a CTE or a `UNION` on MySQL and MariaDB, a compound `SELECT` or `VALUES` on SQLite. One of those words inside a value, such as a filter on `'union'`, counts too.

On the Mac, these cannot trace a column: ClickHouse, Redis, CockroachDB, Redshift, TiDB, Databend, OceanBase, a SQLite [remote file](/connections/remote-database-files) opened **On the Server**, and every engine from the plugin registry. On a connection with rules, every column of a query on them comes back masked, and a browsed or exported table is matched by column name, as in the grid.

### On a connection with rules

On the Mac, the rules also withhold text that can repeat a stored value:

| Where | What comes back |
|-------|-----------------|
| A statement that fails | The error code and SQLSTATE where the driver reports them, and a sentence saying the message is withheld |
| **Fix with AI** | The failed statement, without the server's message |
| A query plan | The plan masked whole, except PostgreSQL's and SQLite's. **Review with AI**, **Explain with AI** and **Optimize with AI** attach no plan on other engines |
| History entries the app wrote from row data, under **Row Edits** and **Imports** | A sentence in place of the statement. A history search with text leaves them out |
| The error of any history entry | A sentence in place of the message |
| Session and slow-query text from the server dashboard | A sentence in place of the statement |

A refusal, a timeout or a cancel from TablePro itself keeps its text. On Linux, a failed MCP query and **Fix with AI** keep the server's error code and withhold its message.

## Editing and Reveal

A mask cannot be written back or used to find its row. On the Mac, a grid that shows a masked column is read-only. On Linux and Windows, a masked cell refuses an edit, and a masked key column locks the whole page.

To see or edit the real values, reveal them in that tab:

| App | Choose | Then confirm with |
|-----|--------|-------------------|
| Mac | **Reveal Masked Values…** on a masked column's header menu | Touch ID, or your macOS password on a Mac without it |
| Linux | **Reveal Masked Values…** on a masked column's header menu, or under **Column** in a cell's menu | **Reveal** in a dialog |
| Windows | **Reveal masked values...** on a masked column's header menu, or on the menu of a cell in that column | Windows Hello where it is set up, else **Reveal** in a dialog |

The tab reads its rows again unmasked. A query tab whose statement is not a read reveals on its next run instead.

Reveal lasts until the tab closes, or on the Mac until it opens another table. Other tabs stay masked, and so do shared links, the AI assistant and MCP, even from the revealed tab. On the Mac, exports from other tabs stay masked. On Linux and Windows, every export stays masked, the revealed tab's included.

## Limits

Masking hides values on screen and in what TablePro sends out. It does not replace database permissions: anyone with the connection's credentials can read the data with another client. Dumps and backups are not masked either: the files hold the stored values, so keep them as private as the database.

- Filters, sorts and `WHERE` clauses run on the server against the stored values, so a filter on a masked column finds the real matches.
- In the grid, a rule matches the column name a result reports. A query that renames or computes the column, such as `SELECT email AS contact`, shows it unmasked. A **Type** rule catches a renamed column that keeps its type. Results for AI and scripts are [masked by what each column reads](#masking-for-ai-and-scripts).
- **Copy To**, copying objects to another database and Compare move the stored values, not the masks.
- The **Edit Document** sheet shows a stored document's fields without Reveal. Query plans, and the sessions and slow queries on the server dashboard, are not masked in the app.

### Known limits for AI and scripts

A client that may run SQL can still learn a masked value these ways:

- A view, a generated column or a table copied with `CREATE TABLE … AS SELECT` holds the value under its own name. A rule that does not name that column leaves it unmasked, in the grid too. Making the copy is a write, which a **Read Only** token or connection refuses.
- `WHERE` and `ORDER BY` test a value without returning it, such as `WHERE email LIKE 'a%'`. Row counts and row order answer one guess at a time.
- How long a query takes, and whether it fails, can depend on a masked value. A client can probe both, even with the error text withheld.
- A statement a client or a person typed comes back as written, in history and in its own results. So do literals another session sent, wherever the database shows them outside the masked system views.
- On an engine that cannot trace columns, only the system databases and schemas the engine declares are masked whole, not system tables inside a user database. On a SQLite file opened **On the Server**, `sqlite_stat4` and a full-text table's `<name>_content` copy show their columns as your rules name them. CockroachDB's `crdb_internal`, whose lock and contention views print index keys with their values, is not masked whole either.
- Column names are never masked. On MySQL, a client that may prepare statements can build a column name from a value with `PREPARE`.
