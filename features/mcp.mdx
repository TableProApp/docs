Use the bundled `tablepro-mcp` bridge to connect an AI client to your saved connections. The bridge and the `tablepro` command use a private Unix socket. Direct HTTP clients use `127.0.0.1`. Neither listener opens to your network.

This page covers the **Settings > MCP** pane. The protocol itself, the tool catalog, the prompts and the token model live under [Developers](/developers).

## Starting and stopping

Open **Settings > MCP** and turn on **Enable MCP Server**. The **Status** row underneath is how you check it before touching a client config: it reads **Running on port 23508**, or **Stopped**, or **Couldn't start** with the reason below it. **Try Again** beside a failure starts the server again.

With the toggle off, nothing starts the server. A client that launches the bundled `tablepro-mcp` bridge gets "The TablePro MCP server is turned off" within a second instead of a timeout, and pairing an extension stops at the same message with **Open MCP Settings**.

While it is only answering a client, TablePro stays out of the Dock and the app switcher. It appears in both, with its menu bar, once it has a window on screen, including one a client asked it to open. A TablePro the bridge launched while the toggle is off quits again.

The default HTTP port is **23508**. If it is taken, the server binds a free port, shown in **Status**. The bridge uses the socket recorded in the [handshake file](/developers/mcp-protocol#local-socket-and-handshake), so its config needs no port.

## Server configuration

| Setting | Default | Range |
|---------|---------|-------|
| Port | 23508 | |
| Default row limit | 500 | 1 to 500,000 |
| Maximum row limit | 10,000 | 1 to 500,000 |
| Query timeout | 30 seconds | 1 to 300 seconds |
| Log MCP queries in history | on | |

A tool can ask for fewer rows or a shorter timeout, never for more than the maximum.

## Connecting a client

Click **Connect a Client…** and pick **Claude Code**, **Claude Desktop**, **Cursor**, or **Zed**. Each shows numbered steps and a copyable snippet pointing at the bundled bridge. Paste it into the client's own config; TablePro does not write to other apps' files.

For VS Code, Cline, Continue, Windsurf, Antigravity, Goose, the HTTP transport, and a client that connects but lists no tools, see [MCP Clients](/integrations/mcp-clients).

## Connection access

The first time a client reaches one of your connections, TablePro asks. **Approval** under
**Connection Access** decides how often it asks after that.

| Approval | What happens |
|---|---|
| **Ask Every Time** | Every call that names a connection asks first |
| **Ask Once for Each Connection** | The first call asks, and the answer is kept until you revoke it. The default |
| **Never Ask** | Connections are reached without asking |

Leave it at **Ask Once for Each Connection** unless a client runs unattended, in which case **Never
Ask** stops the prompt from waiting for someone who is not there. Approvals already given are listed
underneath, each with **Forget**. A row names the connection and the client it was given to: a
token's name, **Built-in CLI** for the bundled bridge, or [**Claude Agent**](/features/ai-assistant#claude-agent).

Approval decides only whether you are asked. It grants nothing: a connection **Blocked** for
external clients stays blocked, a **Read Only** one stays read only, a connection whose AI policy is
**Never** is refused, and [Safe Mode](/features/safe-mode#external-clients) still confirms
destructive statements. **Never Ask** is not a way to skip any of those.

The question always arrives as a dialog on your Mac, never through the client. A client that could
answer it in its own interface could also answer it without asking you, and this is the gate that
decides whether it reaches the connection at all.

The dialog does not take focus from the app you are typing in. TablePro's Dock icon bounces until
you switch to it, **Deny** is the default button, and Return and Escape both deny. **Allow** takes a
click.

Nothing here times out. Whoever sent the request decides how long to wait for you, and an answer
counts whenever you give it.

### Connections hidden from AI in a launcher

A connection whose AI policy is **Never** is left out of every client's connection list. To see it in
a launcher such as Raycast anyway, turn on **Allow apps to list connections hidden from AI**, then
pair the launcher and tick **List connections hidden from AI** on the approval sheet. The launcher
then lists those connections with their user names, and opens them in TablePro. It still cannot
query them, and Blocked connections stay hidden. Turning the setting off stops every app at once.
Tokens that hold this grant read **Lists connections hidden from AI** in the token list.

## Authentication

Every request needs a token, including one from your own Mac. The server supplies a token to the bundled bridge, so a client set up through **Connect a Client…** needs nothing from you; an HTTP client or a launcher needs a token you generate or pair. Create, scope, allowlist, expire and revoke tokens in this section, described in [Tokens](/developers/tokens).

## Activity and connected clients

**View Activity…** opens the **MCP Activity** window, also on **TablePro > MCP Activity…**. It has two sections:

- **Activity Log**: every authentication, tool call, resource read and query, with the token behind it, the category, the connection, and the outcome. Filter by time, category or token, search, and export the filtered view to CSV. Retained for 90 days. Statements are recorded as a SHA-256 digest, not as text.
- **Connected Clients**: clients that have called in the last five minutes, with the client name, the token, and when they were first and last seen. **Disconnect** revokes that client's token, so the client has to pair again.

## Security model

- Clients work through your saved connections. Passwords never leave the Keychain and are not readable over MCP.
- AI access is set per connection, including blocking a connection from external clients entirely. A blocked connection is not even listed.
- Tokens carry scopes and can be limited to named connections. A request without one gets `401`, from your own Mac too. See [No token, no access](/developers/tokens#no-token-no-access).
- Writes go through the connection's [Safe Mode](/features/safe-mode#external-clients). Destructive statements need a full-access token and approval every time. See [the confirmation tool](/developers/mcp-tools#writing-data).
- Reads use the driver's read-only mode where supported. Statements that access files or run server-side code are refused. [What Read Only allows](/developers#what-read-only-allows) covers engine limits and other refusals.
- The reachable surface is the [tool catalog](/developers/mcp-tools), the [resources](/developers/mcp-resources) and the [prompts](/developers/mcp-prompts). Nothing else.
- Reaching the server from another machine means forwarding the port over SSH yourself, and owning what that exposes.
