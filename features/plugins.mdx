## Installing plugins

A registry plugin installs where you need it:

- A database type badged **Not Installed** in the connection chooser.
- A `.duckdb` file opened from Finder, which asks for the DuckDB driver.
- **Install Parquet…** at the end of the format menu in the Export dialog. Parquet is selected once the download finishes.

On a Mac with no network, install from a file: drag a `.tableplugin` or `.zip` onto **Settings > Plugins**, or click the **+** button there. User-installed plugins live in `~/Library/Application Support/TablePro/Plugins`.

Every plugin is verified before it loads. A registry download must match the SHA-256 checksum in the registry manifest, and the bundle must be signed by TablePro. A bundle signed by anyone else, ad-hoc signed or unsigned is refused, with no override.

## Updates

The Plugins settings tab carries a badge counting pending updates and plugins that failed to load. Select a plugin in **Settings > Plugins** to see its installed version, then click **Update**.

If a driver has open connections, the update is staged instead of applied. The staged version activates when the last connection using the driver closes, or click **Activate Now** after closing them. Quit before it activates and the update is offered again on next launch.

## After an app update

An app update can raise the plugin interface version. Plugins built against the old version are rejected at load instead of crashing, and TablePro repairs them itself: at launch it reinstalls a compatible build of each outdated plugin, retrying in the background if the registry is unreachable. Connecting to a database whose plugin is outdated updates that plugin first.

Until a plugin is repaired, it appears in a banner in **Settings > Plugins** with the reason and an action:

| Action | Meaning |
|--------|---------|
| **Update Now** | A compatible build is in the registry. One click installs it. |
| **Update TablePro** | The plugin requires a newer app version. |
| No button | No compatible build is published yet. TablePro retries automatically. |
| **Remove** | Deletes the rejected plugin from disk. |

## Managing plugins

In **Settings > Plugins**:

- **Uninstall** removes a user-installed plugin from disk. Bundled plugins cannot be uninstalled.
- The detail pane shows version, bundle ID, capabilities, database type, and default port. Plugins with their own settings show them here.

macOS cannot fully unload a plugin's code until relaunch, so a banner offers **Quit & Reopen** after you remove one.

Saved connections survive a removal. A connection whose driver cannot load stays in the list, and opening it lands on "Could not connect" with the button for the cause:

| Cause | Button |
|-------|--------|
| The driver is not installed | **Install Plugin…** downloads it and connects |
| The plugin failed to load or needs an update | **Open Plugin Settings** selects it in **Settings > Plugins**. Click **Try Again** once it is fixed |
| The connection names a database type no plugin provides, which a connection imported from another app can | **Edit Connection…** opens the form to choose the type |
